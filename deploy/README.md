# Деплой на Google Cloud (бесплатная машина e2-micro)

Игра работает на одной виртуальной машине: сервер на Go за Caddy, который получает и продлевает
HTTPS-сертификат Let's Encrypt. Игроки, счёт встреч и идущие партии хранятся в `/var/lib/gogame`
на диске машины. При остановке сервер сохраняет партии, при запуске восстанавливает их, а браузеры
игроков переподключаются сами: перезапуск партию не обрывает, на время перезапуска часы стоят.

Сейчас игра работает по адресу https://rombl-go.duckdns.org (машина `gogame`, IP 35.209.168.96).

## Что входит в бесплатный тариф (Always Free)

- 1 машина **e2-micro** в регионах **us-west1**, **us-central1** или **us-east1**. В других регионах она платная.
- Диск **Standard persistent disk** до 30 ГБ. Диски Balanced и SSD платные.
- 1 ГБ исходящего трафика в месяц. Игре этого хватает: страница весит около 150 КБ, ходы — несколько байт.

Условия меняются, поэтому сверяйтесь со страницей https://cloud.google.com/free перед созданием машины.

## 1. Аккаунт и проект

1. Войдите на https://console.cloud.google.com. Чтобы включить биллинг, нужна банковская карта: без неё
   машину создать нельзя, но в рамках бесплатного тарифа деньги не списываются.
2. Создайте проект, например `go-game`.
3. Сразу настройте бюджет с оповещением: **Billing → Budgets & alerts → Create budget**, сумма $1.
   Так вы узнаете о любом списании.

## 2. Ключ SSH (на вашем компьютере)

```bash
ssh-keygen -t ed25519 -f ~/.ssh/gogame_gcp -C deploy
```

```bash
cat ~/.ssh/gogame_gcp.pub
```

Комментарий `deploy` станет именем пользователя на машине.

## 3. Машина

**Compute Engine → VM instances → Create instance:**

- **Name:** `gogame`
- **Region:** `us-central1` (или `us-west1`, `us-east1`), любая зона
- **Machine type:** `e2-micro`
- **Boot disk → Change:** Debian GNU/Linux 12 (bookworm), тип **Standard persistent disk**, размер 30 ГБ
- **Firewall:** отметьте **Allow HTTP traffic** и **Allow HTTPS traffic**
- **Advanced → Security → Manage access → Add item:** вставьте строку из `~/.ssh/gogame_gcp.pub`
- **Networking:** внешний IP оставьте **Ephemeral** (не резервируйте статический: зарезервированный адрес может быть платным)

После создания скопируйте **External IP** машины.

Внешний IP сохраняется, пока машина работает. Если её остановить и запустить снова, IP может
поменяться — тогда обновите адрес в DuckDNS (шаг 4).

## 4. Домен

Для HTTPS нужно имя домена. Два бесплатных варианта:

- **DuckDNS (рекомендую):** войдите на https://www.duckdns.org через GitHub или Google, создайте имя,
  например `go-roman`, и укажите в поле **current ip** внешний IP машины. Домен: `go-roman.duckdns.org`.
  Если IP поменяется, достаточно обновить его там же — адрес игры останется прежним.
- **sslip.io (без регистрации):** домен получается из IP, точки заменяются на дефисы: для IP
  `34.123.45.67` это `34-123-45-67.sslip.io`. Если IP поменяется, поменяется и адрес игры.

## 5. Первая установка (на вашем компьютере, из папки проекта)

```bash
deploy/deploy.sh deploy@<External IP> --setup <домен>
```

Скрипт собирает клиент и сервер, загружает их на машину и один раз настраивает её: ставит Caddy,
создаёт пользователя `gogame`, файл подкачки 1 ГБ и службу systemd. В конце он должен вывести `active`.

Через минуту игра будет доступна по адресу `https://<домен>`. В первый раз Caddy получает
сертификат, поэтому первое открытие может занять несколько секунд.

## 6. Обновление

Обновление идёт само: каждая зелёная сборка ветки `main` на GitHub деплоится на машину
(`.github/workflows/ci-cd.yml`). Вручную, с вашего компьютера:

```bash
deploy/deploy.sh deploy@<External IP>
```

Партии перезапуск переживают: сервер сохраняет их при остановке и восстанавливает при запуске.

## 7. CI/CD на GitHub

- **CI:** на каждый push и pull request — проверка типов и сборка клиента, `go vet` и тесты сервера.
- **CD:** после зелёной сборки `main` — `deploy/deploy.sh` по SSH.
- Единственный секрет репозитория — `DEPLOY_SSH_KEY`, закрытый ключ отдельного пользователя деплоя
  (у вас он в `~/.ssh/gogame_ci`). IP машины и её отпечаток SSH публичные и лежат в workflow и в
  `deploy/known_hosts.txt`: подменить сервер не получится.
- Если IP машины поменяется: обновите его в DuckDNS, в `.github/workflows/ci-cd.yml` и в
  `deploy/known_hosts.txt` (команда `ssh-keyscan -t ed25519 <новый IP>`).
- Отозвать доступ GitHub к машине: удалите строку `github-actions-deploy` из
  `~deploy/.ssh/authorized_keys` на машине.

## Полезные команды на машине

Подключиться:

```bash
ssh -i ~/.ssh/gogame_gcp deploy@<External IP>
```

Журнал игры:

```bash
sudo journalctl -u gogame -n 100 --no-pager
```

Журнал Caddy (сертификаты, HTTPS):

```bash
sudo journalctl -u caddy -n 100 --no-pager
```

Резервная копия данных (игроки и счёт встреч):

```bash
scp -i ~/.ssh/gogame_gcp -r deploy@<External IP>:/var/lib/gogame ./gogame-backup
```

Файлы в `/var/lib/gogame` принадлежат пользователю `gogame`. Если `scp` не может их прочитать,
сначала скопируйте их на машине: `sudo cp -r /var/lib/gogame /tmp/ && sudo chown -R deploy /tmp/gogame`.
